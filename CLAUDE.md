## Claude-only

- **Model: pin `opus-5` (canonical `claude-opus-5`).** Opus 5 is the operational Anthropic review/judgment seat. Opus 4.8 remains a time-bounded compatibility fallback while it is genuinely available. Direct `claude` without teamclaude is `auth_blocked` and is not a working route. Keep the model from silently falling to Sonnet via the `availableModels` allowlist (include `claude-opus-5` and `fable-5` if granted; exclude `sonnet-5` if you want a hard refusal over a silent drop).
- **Fable 5: rare architecture / long-horizon escalation, OUT of the gating order.** Same Anthropic family as Opus — never a second family for a cross-family gate. Never a gating reviewer, never a sole gate, never the default implementer. Opus 5 is currently stronger and more efficient for normal Anthropic judgment. Confirm the Fable grant with `bin/detect-capability.py`.
- **Five Claude seats via teamclaude:** Max + 2 Team-premium (Fable-capable) + 2 Pro (Opus overflow, no Fable). Route through **teamclaude** so it rotates across 5h windows and tracks per-model caps (an account out of Opus quota still serves others). Do not stack all work on one account; do not hand-edit routes.
- **Dispatcher mode (as assigned here).** On this machine the user assigned Claude Code as the dispatcher — the Claude orchestration surface (`config/entrypoints.json` `dispatcher.provider` = `opus-5`; a per-setup choice, not a fixed rule — dispatch is user-assigned, and any dispatch-capable seat could hold it). Rankings never grant this authority. It shows status (`bin/usage-status.py`), classifies, stamps review depth, briefs, assigns, gates, and refills — and fans work **OUT** to the orchestration tree: sub-agents (other Claude profiles/seats via teamclaude) plus the specialist seats (Grok implement, GPT Terra MCP, Sol/Opus review, etc.). It **preserves its own account quota by dispatching, not implementing**: do not do implement or review work on this account (read-only legwork — reading a doc, research — via a sub-agent is fine); delegate implement to Grok/seats and any Claude review to *other* live Claude seats, never the dispatcher account. `/orchestrate` runs in this mode.
- **Keep the model from silently downgrading** (verified, `code.claude.com/docs/en/model-config`): the Opus→Sonnet quota downgrade has no first-class opt-out — the `availableModels` allowlist is the lever (exclude `sonnet-5` too if you want a hard refusal over a downgrade). `fallbackModel` is opt-in and fires only on overload, not rate-limits. `switchModelsOnFlag:false` stops safety-flag model swaps. Full guidance for humans: `USER-GUIDE.md`.
- After downgrade to Pro / Team-Standard: losing Fable removes only the optional architecture pass — the **gating order is unchanged: Opus 5 → Codex Sol → Review E (if wired) → stop**. teamclaude `mb/sync-plan` blocks `*fable*` automatically when no seat can serve it; do not hand-edit routes.
