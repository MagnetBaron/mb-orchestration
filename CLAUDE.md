## Claude-only

- **Model: pin `opus-4.8`. Opus 5.0 is forbidden** (default or reviewer) — **the one hard invariant of this system**; Opus 5.1+ are NOT blocked (they slot in via capability+prowess, `providers.json` `model_slot_in`). Enforce the 5.0 block at the harness: `bin/doctor.py` refuses any provider whose model is Opus 5.0, matched exactly by `bin/mborch.py` `is_opus5_zero` (bare `opus-5`, `-0`/`.0`, or a 5.0 build/date stamp; 5.1+ pass). Separately, as an anti-downgrade *preference* (not the invariant), you may list `opus-4.8` in `availableModels` and leave the 5.0 ids out so a stray request refuses rather than running it.
- **Fable 5: architecture only, OUT of the gating order** (owner ruling 2026-08-25, Orchestration Retro — it measured worst on nonsense detection, BullshitBench 0.41 vs Opus 0.94). Never a gating reviewer, never a sole gate, never the default implementer. It is a per-account grant available only while a live Claude seat includes it; confirm with `bin/detect-capability.py`. **Opus 4.8 is the first (Anthropic) gate.**
- **Five Claude seats via teamclaude:** Max + 2 Team-premium (Fable-capable) + 2 Pro (Opus overflow, no Fable). Route through **teamclaude** so it rotates across 5h windows and tracks per-model caps (an account out of Opus quota still serves others). Do not stack all work on one account; do not hand-edit routes.
- **Dispatcher mode (as assigned here).** On this machine the user assigned Claude Code as the dispatcher — the Claude orchestration surface (`config/entrypoints.json` `dispatcher.provider` = `opus-4.8`; a per-setup choice, not a fixed rule — dispatch is user-assigned, and any dispatch-capable seat could hold it). It shows status (`bin/usage-status.py`), classifies, stamps review depth, briefs, assigns, gates, and refills — and fans work **OUT** to the orchestration tree: sub-agents (other Claude profiles/seats via teamclaude) plus the specialist seats (Grok implement, GPT Terra MCP, Sol/Opus review, etc.). It **preserves its own account quota by dispatching, not implementing**: do not do implement or review work on this account (read-only legwork — reading a doc, research — via a sub-agent is fine); delegate implement to Grok/seats and any Claude review to *other* live Claude seats, never the dispatcher account. `/orchestrate` runs in this mode.
- **Keep the model from silently downgrading** (verified, `code.claude.com/docs/en/model-config`): the Opus→Sonnet quota downgrade has no first-class opt-out — the `availableModels` allowlist is the lever (exclude `sonnet-5` too if you want a hard refusal over a downgrade). `fallbackModel` is opt-in and fires only on overload, not rate-limits. `switchModelsOnFlag:false` stops safety-flag model swaps. Full guidance for humans: `USER-GUIDE.md`.
- After downgrade to Pro / Team-Standard: losing Fable removes only the optional architecture pass — the **gating order is unchanged: Opus 4.8 → Codex Sol → Review E (if wired) → stop**. teamclaude `mb/sync-plan` blocks `*fable*` automatically when no seat can serve it; do not hand-edit routes.
