# Mobile development router

Use this router to avoid advertising or reading the full mobile playbook library.

1. Confirm the task actually concerns Dart, Flutter, or native iOS accessibility. Do not trigger merely because a general mobile project exists.
2. Read [references/catalog.md](references/catalog.md). Select one primary leaf playbook. Add a second only when it owns a distinct required validation or deliverable. More than two requires an explicit multi-stage scope.
3. Read the complete selected leaf `SKILL.md` from `~/.codex/skill-library/mobile/<name>/SKILL.md`. Never scan or concatenate all leaf bodies.
4. Follow the leaf workflow while respecting the assignment's file, test, deployment, and approval boundaries. The leaf does not grant tools or broaden scope.
5. Before relying on Dart MCP, confirm its tools are present. Use CLI fallbacks where the catalog permits. If live app, widget-tree, LSP, or hot-reload evidence is required but unavailable, report that validation as blocked rather than inventing it.
6. Return `selected_skills`, files changed or reviewed, tests actually run, and any manual device or assistive-technology validation still required.

For orchestration briefs, Dispatch names only `mobile-dev-router` and its exact `SKILL.md` path. The receiving implementation or review role performs leaf selection. Dispatch does not read leaf bodies.
